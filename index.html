How to read this rotation

Each row is one catalog course. The On-Ground Rotation columns show whether the course meets face-to-face each Fall or Spring, and at what cadence. The Online Rotation columns show which sub-term letters are offered online each semester.

Cadence (on-ground):

Every Year Even Years Odd Years As Needed — not offered

Online term letters (each letter is one section):

A 5-week, Term A B 5-week, Term B C 5-week, Term C F 10-week, First half L 10-week, Last half 15W 15-week online 16W 16-week online AN As needed

In this document, the letter F always means First (10-week first half) — never "Fulton".

Saving: In Chrome/Edge, click Open JSON… to pick a file; after that Save writes in place. In Safari/Firefox, use Save As… to download a JSON file. A yellow "unsaved" badge appears when changes haven't been written yet. All data lives on your computer — nothing is sent anywhere.

Editing: Click any row's Edit button to change title, credits, program, cadence, or term letters. Duplicate creates a modified copy for testing rotation alternatives.

Data source: Seeded from the WWU Registrar course rotation page — 1,158 courses (940 undergraduate, 218 graduate).

Change Requests: Use the Request Change button on any row to submit a change (time/day, instructor, location, add/remove). Requests flow through Pending Approval → Sent to Registrar → Finalized, mirroring the Schedule Change process.

How this view works

Each row is one offering — a single term instance of a course. 5-week slots (A/B/C) land in subterms 1A / 2B / 3C. 10-week courses (F = First, L = Last) appear in both subterms they span. Full-semester online courses are anchored to the 1A subterm for planning.

Fill in Assigned Instructor inline. The Dean and Program Manager columns are auto-assigned from the course mapping. Rows turn red when the assignment deadline has passed and no instructor is assigned.

Click Submit to Registrar when a section is ready — the instructor is locked, the row is tagged SENT, and the button swaps to Request Change for any post-submission edits. Click the + to the left of a course code to add another section of the same course (e.g. ACC 240 01, ACC 240 02).

How this view works

This is the Registrar's queue — the only items that appear here are the ones requiring registrar action. Two sources feed in: section submissions from the Term Assignments page (a Dean clicked Submit to Registrar) and change requests that have been Approved & Sent. Everything else stays out of view.

Click Completed on a row when the Registrar has processed it. The row disappears from this page, the action is recorded in the Changelog, and (for change requests) the request transitions to Finalized.

Use the subterm chips to walk through Fall 1A → Spring 3C → Summer; counts on each chip show how many items still need attention.

How the Change Request workflow works

Submit a change request for any course adjustment — instructor assignments, time/day changes, location moves, add a section, or course adds/cancellations. Requests follow this lifecycle:

Pending Approval → Approved / Rejected → Sent to Registrar → Finalized

Click + New Request to open a new change request, or use Request Change on any assigned course row. A Dean or Associate Provost then reviews — Approve & Send routes the request to the Registrar Queue, or Reject closes it with a reason. The Registrar marks requests Finalized once processed.

How this view works

The Changelog is a chronological feed of every meaningful action that's happened in this scheduler. It pulls from two sources: each section's submission to the Registrar (with timestamp and the instructor that was locked in), and the per-request history entries on every Change Request (creation, approval, rejection, send to registrar, finalize, etc.).

Newest events appear first. Use the search box to find a course code or a person's name, the type filter to narrow to just submissions or just request lifecycle events, and the range filter to focus on recent activity.

Program Managers (CSV upload)

Upload the master course list CSV. The parser auto-detects columns: Course Number & Prefix (course code), Program Manager, and optionally Dean (overrides the school-based Dean assignment). A simple 2- or 3-column CSV (Course Code, Program Manager, Dean) also works. A header row is detected automatically. Each upload replaces the entire mapping. The PM and Dean columns on the Term Assignments page read from this list automatically. Note: the Dean column requires running ALTER TABLE course_program_managers ADD COLUMN IF NOT EXISTS dean text; in Supabase once.
